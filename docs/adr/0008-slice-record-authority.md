# Give each Slice one issue, one document, and one Bead

Status: Accepted

Every executable Slice has exactly one Gitea Issue for approved scope, acceptance
criteria, and human lifecycle; one Planning Document for durable requirements and
design; and one top-level Bead for dependencies and machine readiness. The three
records link to one another and describe the same Slice without sharing authority. A
NightCrew Job is only the runtime claim and execution record. If work must be split,
the new Slice receives all three planning records before it becomes eligible; this
prevents Gitea, Beads, repository documents, and TheNightCrew from becoming competing
backlogs.
